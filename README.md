# Solidity 0.8.39: overlapping recursive storage copy — independent reproduction

[![reproduce](https://github.com/VolodymyrStetsenko/solidity-0.8.39-recursive-copy-repro/actions/workflows/reproduce.yml/badge.svg)](https://github.com/VolodymyrStetsenko/solidity-0.8.39-recursive-copy-repro/actions/workflows/reproduce.yml)

Independent reproduction and measurement of **SOL-2026-8, Overlapping Recursive Storage Struct Copy
Corruption**, fixed in Solidity 0.8.39 (19 November 2026). The bug was reported by
[cyberthirst](https://x.com/cyberthirst) through the Ethereum Foundation bug bounty. The analysis and the fix are
by the Solidity team ([advisory][advisory], [release][release]). This repository checks the advisory against
compiled code and measures what the fix changes.

```solidity
struct Node {
    Node[] children;
    uint256 data;
}
Node root;

root = root.children[0]; // root.data reads back as 0 on 0.8.38 and as 1 on 0.8.39
```

## Key results

solc 0.8.38 against 0.8.39, four builds each: legacy and via-IR, optimizer off and on (200 runs), EVM Osaka,
Foundry 1.7.1.

| Finding | Evidence |
|---|---|
| Corruption in every 0.8.38 build, none in any 0.8.39 build | Tests A–D, G, H, Z |
| Corrupted fields read back as zero or vanish; no wrong non-zero value observed | Z: 6,000 random overlapping copies per build. On 0.8.38, 4,726 are corrupted: 19,975 fields zeroed, 38,943 dropped, 0 wrong non-zero, 0 extra nodes |
| A shallow assertion passes on corrupted state | H: top value, top-level length and first child's value stay correct while 3 of 6 nodes are zeroed or dropped |
| The fix costs gas on every copy, linear in the target size | +417 to +1,247 gas fixed, plus 417 to 541 gas per nested struct in the target. Identical delta with warm and cold storage |
| The depth limit drops unevenly across builds | 38 → 37, 125 → 91, 91 → 91, 201 → 125 |

Every number in this README is generated by `run.sh` and verified by 46 automated checks. Full tables:
[results/summary.md](results/summary.md).

### Cost of the fix (non-overlapping copy)

| Build | Fixed | Per nested struct in the target | Overhead at N = 100, warm / cold |
|---|---|---|---|
| legacy | +1,247 | +541 | +16.1% / +6.7% |
| legacy + optimizer | +527 | +436 | +17.4% / +5.9% |
| via-IR | +492 | +478 | +14.9% / +6.0% |
| via-IR + optimizer | +417 | +417 | +16.6% / +5.6% |

### Depth limit

Deepest target chain a non-overlapping copy can overwrite before the EVM stack (1024 items) overflows.

| Build | 0.8.38 | 0.8.39 |
|---|---|---|
| legacy | 38 | 37 |
| legacy + optimizer | 125 | 91 |
| via-IR | 91 | 91 |
| via-IR + optimizer | 201 | 125 |

The advisory reports 252 → 126 for its own example (via-IR + optimizer). Different struct and copy, so the
baselines differ.

## Reproduce

```bash
git clone https://github.com/VolodymyrStetsenko/solidity-0.8.39-recursive-copy-repro
cd solidity-0.8.39-recursive-copy-repro
./run.sh
```

Requirements: [Foundry](https://getfoundry.sh) and Python 3 (standard library only). `forge` downloads solc 0.8.38
and 0.8.39 itself. The script runs all tests in eight builds (about 10 seconds), records the settings solc actually
used from the artifact metadata, writes `results/raw.txt` and `results/summary.md`, and exits non-zero if any check
fails.

[CI](.github/workflows/reproduce.yml) runs the same script on every push with Foundry v1.7.1 and fails if the
regenerated summary differs from the committed one. Gas figures may differ with other Foundry versions.

## Tests

| ID | What it shows |
|---|---|
| A | The advisory's example, `root = root.children[0]` |
| B | The same overlap through a storage pointer parameter and a mapping key: `nodes[7] = src` with `src = nodes[7].children[0]` |
| C | Array form, `roots = roots[0].children` |
| D | Value field declared first: the top value survives, a deeper value is lost |
| G | Full dump of a 6-node subtree after the copy |
| H | Shallow assertion against deep comparison with a memory snapshot |
| Z | Random differential test: 3 layouts × 2 copy forms × 1,000 copies |
| E, J | Gas of a non-overlapping copy, warm and cold storage |
| K | Depth limit scan |

## Methodology

### Struct layouts

```solidity
struct Node { Node[] children; uint256 data; }          // array first: A, B, C, E, J, K; Z "ArrayFirst"
struct Node { uint256 data; Node[] children; }          // value first: D, G, H; Z "DataFirst"
struct Node { uint256 a; Node[] children; uint256 b; }  // both: Z "Sandwich"
```

### Shallow against deep (G, H)

Value field declared first. Copy `root = root.children[0]`:

```
before                          after, 0.8.38                   after, 0.8.39
root{100}                       root{1}                         root{1}
└─ S{1}      <- source          ├─ {2}                          ├─ {2}
   ├─ A{2}                      │  ├─ {4}                       │  ├─ {4}
   │  ├─ {4}                    │  └─ {0}     zeroed            │  └─ {5}
   │  └─ {5}                    └─ {0}        zeroed, child     └─ {3}
   └─ B{3}                                    {6} dropped          └─ {6}
      └─ {6}
```

Only the leftmost path (1 → 2 → 4) keeps its values. The shallow assertion
`root.data == 1 && root.children.length == 2 && root.children[0].data == 2` passes on both versions. The deep
check compares the whole result recursively with `Node memory expected = root.children[0]`, taken before the copy.
It fails on 0.8.38 and passes on 0.8.39. A storage-to-memory copy is not affected by this bug (the corrupting copy
is always storage-to-storage), so the snapshot is a valid oracle.

### Random differential test (Z)

- Generator: keccak256 chain, seeded with `keccak256(abi.encode("solc-0.8.39-repro", layout, form))`.
- Shape: 1–3 top-level nodes; each gets a subtree of depth 1–4; every node above the depth limit has 0–3 children
  (all uniform). Copied subtrees hold 6.6 nodes on average, 60 at most.
- Values: a global counter, so every value is unique and non-zero and any wrong value is detectable.
- Copy: source index `k` uniform over the top-level nodes. Forms `trees[t] = trees[t].children[k]` and
  `lists[t] = lists[t][k].children`.
- Oracle: memory snapshot of the source taken before the copy.
- Every field (value or array length) of the expected result is classified as correct, zeroed, wrong non-zero,
  or dropped (its node is missing because an array came back shorter). Nodes that should not exist count as extra.
- 1,000 copies per layout and form, 6,000 per build. The four builds of each version produce identical counts.

### Gas (E, J)

- Target: a mapping entry holding N leaf nodes, N = 0, 10, ..., 100. Source: a separate entry with one leaf child.
  The copy does not overlap.
- `gasleft()` around the assignment: execution gas, before refunds, without transaction base cost.
- Warm: all slots written earlier in the same transaction. Cold: `vm.cool(address(this))` right before the copy.
- Delta = 0.8.39 − 0.8.38 for the same build and N, fitted by least squares as `fixed + perStruct × N`. The fit is
  exact in every build (residual 0).
- "Identical with warm and cold storage" refers to the delta. Absolute cost differs, so percentage overhead is
  specific to this harness.
- At N = 0 the 0.8.38 copy costs more than at N = 10 because it has to grow an empty array (zero to non-zero
  writes). The delta is unaffected.

### Depth (K)

- Target: a linear chain of depth d (one child per node). Source: an empty node. The copy does not overlap.
- Success: the external call returns without reverting. Linear scan d = 1..260, 200M gas per attempt.
- `run.sh` reads the `-vvvv` trace: every failure is `EvmError: StackOverflow` (the EVM operand stack exceeds 1024
  items), none is out-of-gas, and there is a single threshold per build.
- 0.8.38 has a limit too, because clearing the old deep target is itself recursive; 0.8.39 adds the overlap walk.

## Scope and limits

- Synthetic single-transaction harness on Foundry's EVM (revm). Gas deltas are measured on leaf-node targets; the
  advisory states that the cost of the check grows linearly with the number of nested structs in the target.
- "No wrong non-zero value" is an empirical result for these layouts, shapes and copy forms, not a proof.
- Covered by the advisory but not tested here: mutual recursion (`NodeA → NodeB → NodeA`) and copies between
  implicitly convertible types, such as a static array copied onto a longer one that contains it.
- Per the advisory, `push()` cannot trigger the bug (it copies in the opposite direction). The reverse assignment
  `root.children[0] = root` remains undefined behaviour in 0.8.39 and is not tested here.

## Triage

Derived from the conditions in the advisory:

1. Does a struct reach its own type through a dynamic array, directly or via other structs?
2. Is the struct, or an array of it, copied storage-to-storage?
3. Can the target contain the source at any depth, including via a storage pointer, a mapping key or an array index?
4. Does the corrupted value reach a read, comparison or transfer, in the same or a later transaction?

Recompiling does not repair storage that an earlier copy already corrupted; the advisory recommends reviewing it.
Since corrupted fields look like default values, the current storage alone cannot separate intact from damaged
state. Reconstructing the expected state needs history: events or a replay. The Solidity team's Sourcify scan
covered verified contracts at the time of the advisory and found no affected copy.
